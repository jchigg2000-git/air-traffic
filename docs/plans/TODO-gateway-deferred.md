# Inference gateway — deferred work ledger

*Phase 3 (see [`phase-3-inference-gateway.md`](./phase-3-inference-gateway.md)) shipped the MVP slice: G0, G1, G2, partial-G6 (Presidio), G7, the Gateway Harness tab, and flywheel v0. Everything below is deliberately deferred; full specs live in the G-blocks of [`../inference-gateway-build-plan.md`](../inference-gateway-build-plan.md) §5.*

## Deferred G-blocks

- **G3 — Reversible tokenize + Redis vault + SSE boundary buffering.** Only `mask`/`block`/`detect` ship today; `tokenize` is rejected at config load. The credbroker recognizes `vault:`/`kms:` refs but errors on them (env: only).
- **G4 — Async monitor + in-pod capture buffer + dual tee.** No response-side enforcement: the harness's SSE straddle cases score the *reassembly scanner* (detect-only, informational `response_leaks`), not a response gate.
- **G5 — Tokenization oracle.** Needs the G3 vault.
- **G6 (remainder) — Managed DLP adapters** (Comprehend Medical / Google DLP / Azure PII, BAA-gated). Presidio self-hosted tier shipped, and the config-knob slice was pulled forward 2026-07-02 (deny-list + per-type threshold proposal kinds with probe evidence, context words on regex rules — `PERSON_NAME` now has an approvable artifact). Still deferred: managed-DLP adapters and policy-selected engine routing per route (chain is static from `GATEWAY_DETECTORS`).
- **G8 (remainder) — OTel depth.** Gateway telemetry is slog JSON + spine metrics; no OTel SDK, no trace spans. *The log-leak CI wiring landed 2026-07-30:* `.github/workflows/ci.yml` runs the guard (`TestNoRedactedValueInLogsOrAudit` + the harness full-loop test) as its own named job, so a regression reads as "Log-leak guard failed", not one line inside a full test run.
- **G9 — Horizontal-scale hardening.** Single replica; no Redis budget counters, no hard cross-vendor spend stop, no HPA/drain. The dependency isolation + stateless-pod shape is in place. **Blocked by design, not by effort:** a Redis-backed counter needs a Redis client, and this repo is stdlib-only (CI now fails the build if a `go.sum` appears). Doing G9 honestly means either accepting the first third-party dependency or writing a RESP client by hand — a scope decision for the owner, not something to slip in under a hardening pass. Until then, the single-replica shape is what the docs claim.
- **G10 (full) — LLM-judge labeling, Synthea generation, shadow mode.** Flywheel v0 is harness-ground-truth + curated candidate library + human approval only. No learned patterns, no NER fine-tuning (no-GPU local ceiling — deliberate).

## Closed 2026-07-30

- **Auth on the `/api/gateway/*` spine routes.** `AIRTRAFFIC_SPINE_KEY` gates `leaks`, `enforcement`, and `patterns` (Bearer or `X-Air-Traffic-Key`, constant-time compare); unset falls back to loopback-only rather than open. `/status` stays public (browser liveness, no terms) and now reports the posture — `spine_auth`, `spine_key_unrotated`. Gateway side: `GATEWAY_CONTROL_PLANE_KEY_REF`, stamped on every push *and* pull. `internal/server/spine_auth*.go`, `internal/gateway/spine_emit.go`.
- **Key rotation path.** `scripts/dev-env.sh` mints random `GATEWAY_CLIENT_KEYS` + `AIRTRAFFIC_SPINE_KEY` into a gitignored `.env` (compose reads it automatically; `--rotate` replaces). The compose fallbacks (`gwk-demo` / `spine-dev-insecure`) still exist so the demo comes up in one command, but both binaries log a warning while they are live and the status route reports them as unrotated. The default is now *loud*, not silent — it is still not safe to deploy shared without running the script.
- **Multimodal / tool-call field walk.** The adapter now walks `tool_result` content (string and nested blocks), `tool_use.input` (every string leaf, depth-bounded), `document` text sources plus `title`/`context`, and `tools[].description`. Verified live: a request carrying PII in tool_use input, tool_result content, and a document source came back `redactions=4, types=CREDIT_CARD×1, EMAIL×1, SSN×2`. **Still deliberately unwalked:** image and base64-document payloads (PII in pixels needs OCR — scanning base64 finds nothing, so claiming to scan it would overstate enforcement; *blocking* such blocks is a policy question for G4) and `thinking`/`redacted_thinking` blocks (server-signed; rewriting the text invalidates the signature).
- **SSE usage extraction.** `copyStream` tees the relayed bytes through a usage scanner reading `message_start.usage.input_tokens` and `message_delta.usage.output_tokens`, so streamed requests report tokens like non-streaming ones. Relay stays byte-faithful and per-read flushed; the partial-line buffer is capped at 1 MB. Verified live on the compose stack (`tokens_in: 27, tokens_out: 13` for a streamed request that previously reported zero).
- **CI.** `.github/workflows/ci.yml`: Go (gofmt, stdlib-only guard, vet, build, `test -race`), the log-leak guard as its own job, web (typecheck/build/vitest), and both Docker image targets.

## Slice-local deferrals (from this build)

- **`cost_usd` pass-through:** gateway emits `tokens_in/out` but not dollars — fabricating a price table would violate the honesty model. Wire real pricing when a source of truth exists.
- **OpenAI-compatible dialect:** Anthropic Messages only (`/v1/messages`); `adapter_openai.go` is additive behind the same walk seam.
- **Response-side field walk:** the deep walk above is request-side. Responses are relayed byte-faithfully; response-side enforcement is G4.
- **Audit-ring pressure at volume:** per-request gateway reports live in a 5000-cap ring; only blocks/fail-trips hit the audit stream. Fine for harness scale; revisit with G8.
- **Presidio custom-recognizer YAML mount:** pattern-pack rules — including the deny-list and context-word knobs added 2026-07-02 — ride per-request `ad_hoc_recognizers`; a mounted recognizer config (lower per-call payload, survives analyzer restarts independently) remains deferred.
- **Showcase readiness:** no live/hosted demo — seeing the Flight Deck or Gateway Harness still means running `docker compose up -d --build` locally (control plane :8122, gateway :8125, Presidio :8126). A hosted read-only instance or a recorded walkthrough is an owner decision (it publishes the app), not a hardening item.
- **`web/src/lib/dispositions.ts` copy:** the `proxy_enforced` blurb still says "off by default"; the Policy Editor outcome chip is already truthful (`applied_proxy`), so this is cosmetic.
