- **G4 — Async monitor + in-pod capture buffer + dual tee.** No response-side enforcement: the harness's SSE straddle cases score the *reassembly scanner* (detect-only, informational `response_leaks`), not a response gate.

- **G6 (remainder) — Managed DLP adapters** (Comprehend Medical / Google DLP / Azure PII, BAA-gated). Presidio self-hosted tier shipped, and the config-knob slice was pulled forward 2026-07-02 (deny-list + per-type threshold proposal kinds with probe evidence, context words on regex rules — `PERSON_NAME` now has an approvable artifact). Still deferred: managed-DLP adapters and policy-selected engine routing per route (chain is static from `GATEWAY_DETECTORS`).
- **G8 (remainder) — OTel depth.** Gateway telemetry is slog JSON + spine metrics; no OTel SDK, no trace spans. *The log-leak CI wiring landed 2026-07-30:* `.github/workflows/ci.yml` runs the guard (`TestNoRedactedValueInLogsOrAudit` + the harness full-loop test) as its own named job, so a regression reads as "Log-leak guard failed", not one line inside a full test run.
- **G9 — Horizontal-scale hardening.** Single replica; no Redis budget counters, no hard cross-vendor spend stop, no HPA/drain. The dependency isolation + stateless-pod shape is in place. **Blocked by design, not by effort:** a Redis-backed counter needs a Redis client, and this repo is stdlib-only (CI now fails the build if a `go.sum` appears). Doing G9 honestly means either accepting the first third-party dependency or writing a RESP client by hand — a scope decision for the owner, not something to slip in under a hardening pass. Until then, the single-replica shape is what the docs claim.
- **G10 (full) — LLM-judge labeling, Synthea generation, shadow mode.** Flywheel v0 is harness-ground-truth + curated candidate library + human approval only. No learned patterns, no NER fine-tuning (no-GPU local ceiling — deliberate).

## Closed 2026-07-30

- **Auth on the `/api/gateway/*` spine routes.** `AIRTRAFFIC_SPINE_KEY` gates `leaks`, `enforcement`, and `patterns` (Bearer or `X-Air-Traffic-Key`, constant-time compare); unset falls back to loopback-only rather than open. `/status` stays public (browser liveness, no terms) and now reports the posture — `spine_auth`, `spine_key_unrotated`. Gateway side: `GATEWAY_CONTROL_PLANE_KEY_REF`, stamped on every push *and* pull. `internal/server/spine_auth*.go`, `internal/gateway/spine_emit.go`.
- **Key rotation path.** `scripts/dev-env.sh` mints random `GATEWAY_CLIENT_KEYS` + `AIRTRAFFIC_SPINE_KEY` into a gitignored `.env` (compose reads it automatically; `--rotate` replaces). The compose fallbacks (`gwk-demo` / `spine-dev-insecure`) still exist so the demo comes up in one command, but both binaries log a warning while they are live and the status route reports them as unrotated. The default is now *loud*, not silent — it is still not safe to deploy shared without running the script.
- **Multimodal / tool-call field walk.** The adapter now walks `tool_result` content (string and nested blocks), `tool_use.input` (every string leaf, depth-bounded), `document` text sources plus `title`/`context`, and `tools[].description`. Verified live: a request carrying PII in tool_use input, tool_result content, and a document source came back `redactions=4, types=CREDIT_CARD×1, EMAIL×1, SSN×2`. **Still deliberately unwalked:** image and base64-document payloads (PII in pixels needs OCR — scanning base64 finds nothing, so claiming to scan it would overstate enforcement; *blocking* such blocks is a policy question for G4) and `thinking`/`redacted_thinking` blocks (server-signed; rewriting the text invalidates the signature).
- **SSE usage extraction.** `copyStream` tees the relayed bytes through a usage scanner reading `message_start.usage.input_tokens` and `message_delta.usage.output_tokens`, so streamed requests report tokens like non-streaming ones. Relay stays byte-faithful and per-read flushed; the partial-line buffer is capped at 1 MB. Verified live on the compose stack (`tokens_in: 27, tokens_out: 13` for a streamed request that previously reported zero).
- **CI.** `.github/workflows/ci.yml`: Go (gofmt, stdlib-only guard, vet, build, `test -race`), the log-leak guard as its own job, web (typecheck/build/vitest), and both Docker image targets.

## Closed 2026-08-15 (second pass) — the flywheel can now lower a false positive, not just raise recall

- **`allow_list` pattern-rule kind.** Until now every rule kind ADDED a detection (regex, deny_list) or gated one by score (threshold). Nothing could say "this exact term is not PII." That gap was invisible while the only traffic was seeded harness traffic with exact ground truth; it became load-bearing the moment two real apps ran through the gateway under a `block` baseline.
  - **Why a threshold could not do it:** spaCy returns **0.85 for every PERSON and LOCATION it finds, true or false**. Measured, not assumed — `Alice Whitfield`, `Margaret Chen`, `Springfield`, `Pennsylvania Avenue NW` and the false `Portugal`, `Brazil`, `Spider-Man`, `JSON` all score exactly 0.85. Any gate that suppresses one suppresses the other; the score carries no signal to separate them.
  - **Where it is applied:** `Chain.Run` (`internal/gateway/detect/detector.go`), beside `typeGuards` and for the same reason — suppression must overrule *whichever* engine made the claim, so a term the owner ruled out cannot return because a different detector found it. Matching is on the span's own text, case-insensitively, scoped to the type it was approved for. It suppresses a **term**, never a region, so it cannot be used to hide real PII by neighbouring it (pinned by `TestAllowListDoesNotShieldNeighbouringSpans`).
  - **Trust boundary:** `ruleFromProposal` gets the strictest check of any kind — bounded count, no whitespace-padded/empty terms, no line spans, and a shorter max length than a deny term (48 vs 80 bytes), because the longer the string the more likely it is an attempt to switch a type off wholesale.
- **`POST /api/harness/proposals`** — owner-authored proposals. The flywheel's own proposals are recall-driven: they come from harness misses, and it has **no ground truth for real application traffic**, so it can never infer that a detection was wrong. A false positive seen in production is therefore a human judgement, and this routes it through the same propose → approve → hot-reload path with the same audit trail rather than becoming a hardcoded exception in the detector. Authoring and approving stay separate acts; nothing auto-approves.
- **Live result.** Under the `healthcare` baseline (action `block`), meaning-to-making's stage-1 call was blocked on **100% of turns** by five false positives in its own static system prompt: `Spider-Man`, `Dogman`, `Pokemon`, `Mario` (its `CHILD_INTERESTS` list, read as PERSON) and **`JSON`** (from *"Output ONLY the JSON object"*, read as LOCATION → ADDRESS). The app returned HTTP 200 throughout — it catches the failure and serves its degraded path — so the outage was invisible from outside. After approving two allow-list rules (pack v5, v6) all three stage-1 calls pass at 1362–1363 tokens, while `SSN`, `EMAIL` and a real `PERSON_NAME` are still blocked, and the harness is unmoved: `E2E_COMPOSE=1 ./scripts/e2e-gateway.sh` 9/9, recall_behavioral 1.000, precision 0.991, trap FPs 0.
- **Still open, deliberately:** `manual-address-bare-country` (suppressing bare country names like `Portugal`/`Brazil` as ADDRESS) is authored but **left unapproved** — it trades a class of false positives for the chance that a country name is the only address signal in a request, which is an owner call, not an agent's.
- **Note on provenance:** meaning-to-making was the proving ground for this and has since been **unrouted at the owner's instruction** (enterprise app, wrong thing to demo against); every change to that repo was reverted. The findings are kept as the evidence that produced the primitive, not as a live integration. hf-sandbox is the remaining client.

### Opened by the same slice — the pattern pack has no retraction path

`ApproveProposal` only ever appends (`internal/harness/flywheel.go`, `pack.Rules = append(...)`). There is no API, UI, or store method that removes an approved rule; `reject` applies to a *proposal*, before approval. That was tolerable while every kind ADDED enforcement — a stale regex is noise. It is no longer, because `allow_list` **removes** enforcement: an approved suppression is permanent, and a rule whose justification has expired keeps a hole open with nothing to close it.

Live instance of exactly that: `manual-person-m2m-interests` still suppresses PERSON_NAME for `Spider-Man`, `Dogman`, `Pokemon`, `Mario` in the running stack's pack (v6, persisted in the `harness-data` volume), even though the app that justified it is no longer a client. Low severity — those four strings are unlikely to be real PII in enterprise traffic — but it is a standing exception nobody can now retire without wiping the volume, which would also destroy the ratchet history.

What this needs: a retraction path with the same trust boundary as approval (a `POST /api/harness/patterns/{id}/retire` that bumps the pack version, writes an audit event, and marks the originating proposal `superseded`), plus an expiry or review date on `allow_list` rules specifically. Not built.

## Closed 2026-08-15

- **OpenAI-compatible dialect.** `POST /v1/chat/completions` ships beside `/v1/messages`. Both routes run the *same* pipeline (`proxyRequest` in `internal/gateway/proxy.go`) behind a `dialect` descriptor, so a detector or policy change lands on both at once and the two cannot drift. What differs per dialect: the field walk (`adapter_openai.go` — `messages[].content` string or text parts, `messages[].name`, `tool_calls[].function.arguments`, the deprecated `function_call.arguments`, `tools[].function.description`), the usage extractor, the SSE usage scanner, the error envelope, and the upstream auth header. Config gained `GATEWAY_UPSTREAMS[route].auth` (`x-api-key` | `bearer`, defaulting per dialect) so single-route configs written before this keep working untouched.
  - *Deliberately unwalked, same reasoning as the Anthropic adapter:* `image_url` / `input_audio` parts (PII in pixels or audio needs OCR/transcription — scanning base64 finds nothing) and `reasoning` / `reasoning_content` (provider-generated, expected to round-trip verbatim). Tool `arguments` **are** walked as plain text: masking rewrites a span to `[TYPE]`, which carries no quote or backslash, so the JSON-encoded payload stays parseable — pinned by a test.
  - *Verified live* against a local OpenAI-compatible stub: request reached `<base>/chat/completions` with `Authorization: Bearer <upstream cred>` and no `x-api-key`, the client key never left the gateway, `[SSN]`/`[PHONE]` masked in a text part and `[EMAIL]` masked *inside* a `tool_calls` arguments string that still parsed, SSE framing relayed byte-faithfully including the `[DONE]` sentinel, and a streamed response reported `tokens_in=77, tokens_out=21` where the counts previously did not exist for this dialect. Existing suite unaffected: `go test ./...` green, `E2E_COMPOSE=1 ./scripts/e2e-gateway.sh` 9/9 (recall_behavioral 1.000, precision 0.991, trap FPs 0).
  - Note the base-URL seam differs by ecosystem and we follow each convention rather than inventing a third: an Anthropic `base_url` is the bare host (`…anthropic.com` + `/v1/messages`), an OpenAI-compatible one already ends in `/v1` (`…huggingface.co/v1` + `/chat/completions`).
- **Per-request traffic feed.** `GET /api/gateway/requests?limit=N` (public, like `/status`) serves the report ring newest-first, and a **Gateway Traffic** page (`/settings/traffic`) renders it. Before this the ring was read only by the harness scorer — its sole non-store caller was a test — so real application traffic left no visible trace anywhere in the UI. `GatewayRequestReport` gained `model`, `tokens_in`, `tokens_out`; the counts are attached in `record()` so the ring the spine drains and the metrics window cannot disagree. Still metadata-only: types, field paths, offsets, counts, never a value.

## Slice-local deferrals (from this build)

- **`cost_usd` pass-through:** gateway emits `tokens_in/out` but not dollars — fabricating a price table would violate the honesty model. Wire real pricing when a source of truth exists. (Still true after the traffic feed: the feed shows tokens and says plainly why there is no cost column.)
- **Response-side field walk:** the deep walk above is request-side. Responses are relayed byte-faithfully; response-side enforcement is G4. This did not change with the OpenAI dialect — that route guards what the caller sends, not what the model returns.
- **Non-chat OpenAI surfaces:** only `/v1/chat/completions` is proxied. `/v1/models`, `/v1/embeddings`, and the rest are unrouted; a caller needing a model catalogue still talks to the vendor directly.
- **Audit-ring pressure at volume:** per-request gateway reports live in a 5000-cap ring; only blocks/fail-trips hit the audit stream, and the traffic feed reads that same in-memory ring rather than durable storage. Fine for harness scale; revisit with G8.
- **Presidio custom-recognizer YAML mount:** pattern-pack rules — including the deny-list and context-word knobs added 2026-07-02 — ride per-request `ad_hoc_recognizers`; a mounted recognizer config (lower per-call payload, survives analyzer restarts independently) remains deferred.
- **Showcase readiness:** no live/hosted demo — seeing the Flight Deck or Gateway Harness still means running `docker compose up -d --build` locally (control plane :8122, gateway :8125, Presidio :8126). A hosted read-only instance or a recorded walkthrough is an owner decision (it publishes the app), not a hardening item.
- **`web/src/lib/dispositions.ts` copy:** the `proxy_enforced` blurb still says "off by default"; the Policy Editor outcome chip is already truthful (`applied_proxy`), so this is cosmetic.
